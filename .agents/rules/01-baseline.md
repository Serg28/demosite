# Обов'язковий baseline (застосовується завжди)

1. **Не ламати публічну поведінку** без явного запиту.
2. **Явна типізація** для параметрів/повернень у новому або зміненому коді. Новий файл — `declare(strict_types=1)` першим рядком; існуючі файли без нього не чіпати заради самого лише цього.
3. **DI через контейнер/Laravel IoC**, без ручного `new` для сервісів із залежностями.
4. **Валідація в FormRequest**, не в контролерах.
5. **Бізнес-логіка поза Blade** (Controller/Service/Action/DTO).
6. **Мінімальна вкладеність, early return, happy path**.
7. **Без магічних чисел** — константи/enum.
8. **Іменування за Laravel-конвенціями** (Model singular, table plural, method camelCase тощо).
9. **Eloquent first**, Query Builder для складних випадків, raw SQL — лише коли дійсно потрібно.
10. **Безпечна робота з БД**: `$fillable/$guarded`, `findOrFail/firstOrFail`, транзакції для багатокрокових мутацій.
11. **env() тільки в config/**, у коді — `config()`.
12. **Рядки локалізації використовувати за контекстом**:
    - фронт: `__t('Назва')`
    - адмінка: `__cms('Назва')`
    - для JSON-полів моделей (title, name тощо): `$model->t('поле_моделі')`
13. **Без N+1**: eager load відносин через `with()`, у API Resources — `whenLoaded()`.
14. **Безпека (OWASP)**: захист від XSS, SQL injection, CSRF, mass assignment; ніколи `$request->all()` для збереження.
15. **Ефективне кешування**: інвалідація при зміні даних, TTL відповідно до частоти оновлень.
16. **SOLID, DRY, KISS, YAGNI, Event Driven, config driven, Laravel way, Best practice**.
17. **Ідемпотентність** там, де це потрібно (повторний виклик не ламає стан).
18. **Код максимально простий і читабельний з першого погляду**, не ускладнювати, не робити «на майбутнє» якщо це не відповідає задачі. **Висока зв'язність, без дублювання**: повторювані блоки — в окрему сутність (метод/клас/трейт/service), логіка одного домену живе в одному місці, а не розкидана по контролерах, сервісах і Blade.
19. **Заміна FQCN на `use`-імпорти** там, де це безпечно.
20. **Коректна обробка помилок**: не ковтати exceptions, логувати з контекстом. Кожен логічний модуль (домен/сервіс) логує у свій окремий канал (`config/logging.php`) з ротацією (`daily`), а не в загальний `laravel.log`.
21. **Стрелочные функции** где возможно.
22. **Коментарі й докблоки**: лише пояснення чому (не що), зрозуміло без контексту й довідки в іншому файлі; без переказу історії правки чи переліку caller'ів.
    - `//` — до 3 рядків; не влазить — спрощуй код, не коментар.
    - `/** */` — тільки прямо перед оголошенням (клас/метод/властивість/константа), ніколи вільним коментарем у тілі методу.
23. **Структура — за технічним шаром** (`Controller/Service/Action/DTO`), не за доменом. Домен розрісся до кількох файлів — підпапка всередині шару (`app/Services/Checkouts/`, `app/DTO/GiftCertificate/`); один файл — без підпапки.
24. Код для HighLoad, максимальна оптимізація CPU/RAM/DB та opcode.
25. При потребі використовуй VIEW/Generated Columns в БД а також Fibers, Async
26. **Дати/час** — тільки `Carbon`, поточний час — `now()`.
27. **Статика** (зображення, public/) — `asset()`; скомпільовані CSS/JS — `@vite`.
28. **Обробка наборів даних** — Laravel Collections, не масиви; виняток — HighLoad hot-path (п. 24).
29. **Нові повторювані запити** — Query Scopes на моделі, не нові класи в `app/Repository/`. Існуючі Repository-класи чіпати лише за прямим запитом користувача (рефакторинг тощо).
