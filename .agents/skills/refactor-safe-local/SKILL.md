# Безпечний локальний рефакторинг

## Швидка активація (для запитів будь-якою мовою)
- **Використовувати, коли**: треба покращити читабельність/чистоту коду без зміни поведінки.
- **RU сигнали**: сделай простой рефакторинг, рефакторинг без изменения логики, локальный безопасный рефакторинг
- **EN signals**: safe refactor only, non-breaking refactor, readability cleanup without behavior changes
- **Не використовувати, коли**: потрібно змінювати архітектуру, публічні контракти або бізнес-потік.

## Базове правило
Рефакторинг **не змінює логіку та поведінку**. Лише чистка коду, коротші та ясніші конструкції, стандарти стилю.

## Дозволено
- Рефакторинг у межах стандартів з `coding-standards-always` (типізація, DI, naming, коментарі, HighLoad тощо) — не повторювати їх тут.

## Заборонено
- Зміна публічних API/сигнатур/контрактів без окремого дозволу.
- Додавання нових фіч, залежностей, абстракцій «про запас».
- Масові архітектурні рухи між шарами.
- Зміну бізнес-логіки

## Типи та сумісність
- За замовчуванням **не змінювати type hints**.
- Якщо зміна типів критично потрібна для коректності/сумісності, синхронно оновити всі залежні місця (інтерфейси, реалізації, наслідування).

## Команди активації
1. **Рефакторинг локальних неопублікованих змін**
   - Працювати тільки зі зміненими локально PHP-файлами.
2. **Рефакторинг коміту**
   - Уточнити коміт, підтвердити з користувачем, рефакторити тільки його PHP-файли.
3. **Рефакторинг папки: [шлях]**
   - Тільки PHP у вказаній папці та вкладених.
4. **Рефакторинг файла: [шлях]**
   - Лише один конкретний PHP-файл.

## Формат звіту
- Для набору файлів: `Змінено N PHP-файлів`.
- Для одного файла: `Успішно/Неуспішно`.
