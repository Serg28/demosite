# Стандарти коду — fallback-навик

**Використовувати, коли**: `.agents/rules/*.md` ще не в контексті — новий файл, якого ще нема на диску,
словесне питання про стандарти без конкретного файлу, планування до першого Read/Edit.
**Не використовувати для звичайної правки**: якщо `*.php`/`*.blade.php`-файл вже відкривався/редагувався
в цій сесії — правила вже підвантажені автоматично, повторний виклик нічого не додає.
**Сигнали**: применяй стандарты кода всегда / работай по best practices / соблюдай coding standards / always apply coding standards / follow best practices / enforce baseline rules.
**Не використовувати, коли**: потрібен окремий режим рефакторингу — див. refactor-safe-local / refactor-global-architecture.

## Джерело правил
Повний перелік стандартів живе в `.agents/rules/` (симлінк `.claude/rules/`) і підвантажується автоматично в контекст, щойно відкривається `*.php` / `**/Console/Commands/*.php` / `*.blade.php`:

- `01-baseline.md` — базові правила (типізація, DI, валідація, локалізація, кешування, логування по каналах, доменне групування папок тощо)
- `02-observers.md` — реєстрація Observer-ів через `#[ObservedBy]`
- `03-di-lifecycle-octane.md` — singleton/scoped/bind, Octane-safety (у цьому проєкті Octane не встановлений — пункти превентивні)
- `04-artisan-commands.md` — правила для Artisan-команд
- `05-anti-patterns.md` — заборонені патерни + межі змін (refactor-safe-local / refactor-global-architecture)
- `06-checklist.md` — фінальний чекліст + token-efficient короткий режим
- `07-naming.md` — іменування (Laravel-конвенції; Action — без суфікса, як у поточному коді проєкту)
- `08-livewire-security.md` — авторизація в Livewire 4-компонентах (Fortify/`Auth::user()`)

Цей файл нічого не дублює — якщо треба звірити конкретне правило, читай відповідний файл у `.agents/rules/`.

## Роль цього навика
Навик — це тригер дії, а не джерело контенту:
1. Перед тим як вважати PHP/Blade-задачу завершеною — пройтися по `06-checklist.md`.
2. Якщо в зміненому коді є щось із `05-anti-patterns.md` — виправити до завершення.
3. Якщо з якоїсь причини файли `.agents/rules/` не підвантажились автоматично (немає символьного посилання, зміни поза `*.php`/`*.blade.php`) — прочитати їх вручну перед правкою.

## Нова архітектура (Actions/DTO/custom query builders/strict_types)
Скіли `laravel-architecture`, `laravel-actions`, `laravel-dtos`, `laravel-query-builders` та інші
з родини `laravel-*` (джерело: `leeovery/agentic-skills`) містять цільову, суворішу архітектуру.
Правило — "Consistency First", застосоване по межі зони, а не по всьому проєкту одразу:

- **Нова ізольована область** (нова модель/фіча, яка не чіпає існуючі Service-класи) — писати
  одразу по новій архітектурі, конфліктувати нема з чим.
- **Розширення існуючого Service-коду** (новий метод у наявному Service, правка існуючого файлу) —
  лишатися в поточному стилі проєкту. Не розколювати один зв'язний шматок логіки на два діалекти
  посеред файлу — це гірше за сам факт "старого" стилю.
- **Явний запит на рефакторинг існуючого коду під нову архітектуру** — окремий сценарій, див.
  `refactor-global-architecture`.

Не певен, до якої категорії належить конкретна задача — запитати користувача, а не вгадувати.
